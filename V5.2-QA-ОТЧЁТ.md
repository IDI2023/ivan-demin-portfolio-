# Проверка портфолио V5.2

## Результат

- **44/44** проверок взаимодействия и адаптивности прошли в изолированном Chromium с HTML, CSS, JS и встроенными исходными изображениями, но **без полноценной загрузки MP4 по HTTP**.
- **38/38** проверок связей файлов, данных, исходников и сборки прошли (`verify_v52.py`).
- Прямые ссылки на пять видео «СамаРамён» и слайды Buldak сохранены как резервный путь без JavaScript.
- Все шесть видеоработ/карусель имеют свои ссылки на реальные скриншоты статистики.
- Все восемь MP4 присутствуют, кодек видео H.264/yuv420p; проверено, что в новых MP4 «Блеска» атом `moov` расположен до `mdat` (faststart).
- Новые видео «Блеска» побайтово идентичны предоставленным исходникам `IMG_5708(1).mp4` и `IMG_7853(1).mp4`.
- 19 исходников доказательств сохранены отдельно, а ссылки на них включены в GitHub Pages workflow.
- `build.py` пересобирает сайт и проверяет медиафайлы; экспериментальное изменение метрики в изолированной копии успешно меняло HTML. JSON оригинала не менялся.
- YAML-файлы редактора и workflow успешно распарсены.

## Взаимодействия, которые проверены в Chromium

- Нет горизонтального переполнения на **320, 375, 390, 430, 768, 1024, 1440 px**.
- Пять карточек видео открывают и закрывают модальное окно; новая прямая ссылка ведёт к правильному MP4.
- Карусель Buldak открывается и пролистывает 5 слайдов; прямая ссылка ведёт к текущему слайду.
- Шесть кнопок статистики открывают соответствующие доказательства.
- Опрос: HTML-таблица → первый исходник → таблица → второй исходник → таблица → исходная кнопка с возвратом фокуса.
- Видеопросмотр VK-бота открывает диалог.
- JavaScript-исключений в проверенных сценариях не наблюдалось.

## Что НЕ проверено

- **Настоящий iPhone Safari / встроенный просмотрщик ChatGPT на iPhone.** Невозможно подтвердить работу конкретного устройства из среды разработки.
- **Воспроизведение MP4 по опубликованному HTTPS.** Локальную навигацию к тестовому HTTP-серверу в данной среде блокировала административная политика браузера. В Chromium проверен код диалогов и пути; реальный видеопоток таким способом не декодирован.
- Физический Android Chrome.
- Фактическая публикация на GitHub Pages и её CDN/Range-запросы.
- LCP, INP, CLS на опубликованном домене.
- Полный ручной аудит соответствия WCAG 2.2 AA (проверены только отдельные сценарии доступности).

## Следующая проверка перед откликами работодателям

1. Опубликовать ZIP в GitHub Pages (инструкция в `README-НАЧНИ-ЗДЕСЬ.md`).
2. Открыть опубликованную **HTTPS-ссылку в Safari на iPhone**.
3. Просмотреть все 8 MP4 и каждый из 5 слайдов Buldak, включая прямые запасные ссылки.
4. Открыть все 6 скринов статистики работ, проверить правильность заголовков, цифр и кадрирования.
5. При успешной публикации выполнить Lighthouse/PageSpeed Insights и зафиксировать реальные метрики. 

Протокол автоматических тестов находится в `previews_v5_2/qa-results.json` и `previews_v5_2/static-tests.json`.

## Дополнительный резервный тест без JavaScript

В Chromium с отключённым JavaScript проверено: раскрывающийся список резервных ссылок предоставляет **все пять оригинальных слайдов Buldak**, изображение статистики открывается по `:target` и закрывается по ссылке. Это не проверка воспроизведения видео, но сами видеокарточки содержат прямые ссылки на MP4, которые можно открыть вне модального окна.
